# ①課題名
残り回数（NOKORI KAISU）

## ②課題内容（どんな作品か）
- 「あと何回できるか」を数えるアプリ。やりたいことと年間の頻度を登録すると、健康寿命・平均寿命までの残り年数から残り回数を自動計算して表示する。
- 生年月日・性別・基準（健康寿命と平均寿命）を設定すると、残り年数が自動で算出される。基準を切り替えると残り回数が変わり、「自分で動けるうちにできる回数」と「生きているうちにできる回数」の差が見える。
- 「1回使った」ボタンを押すと残り回数が1つ減る。設定も項目もlocalStorageに保存され、ブラウザを閉じても残る。
- 寿命の数値は厚生労働省の公表値を使用（健康寿命：令和4年 男性72.57歳／女性75.45歳、平均寿命：令和7年 男性81.35歳／女性87.33歳）。

## ⑤工夫した点・こだわった点
- 項目を全部消しても設定は残るようにしたくlocalStorageのキーを2つに分けた：ユーザー設定（`setting`）と登録項目（`items`）を別々に保存することで、「全部消す」と「リセット」で分けている。
- 数字で終わらせず、基準の切り替えで差を見せた：「残り70回」だけでは実感が湧かないため、健康寿命と平均寿命を切り替えられるようにした。同じ項目でも数字が変わることで、残り時間の本質的な意味が伝わるようにした。
- 題材の配慮：入力例に「親に会う」などの特定の人間関係を使わず、「海に行く」のような中立的な例にした。家族構成は人それぞれなため、アプリ側が決めつけるべきではないと考えたため。また「二度と会えない」などといった煽り気味の文言は避け、数字を淡々と出す設計にした。
- 誤操作の防止：リセットは取り返しがつかないため `confirm()` による確認項目を挟んだ。設定前に項目を登録しようとすると警告を出し、計算できない状態を防いだ。
- デザイン：題材が重いため、暗い配色ではなく和紙のような色を基調にした。砂時計のアイコンに加え余白を多めにるまた配色も踏まえ、静かに読める見た目にした。

## ⑥難しかった点・次回トライしたいこと（又は機能）
- 日付の計算：`new Date()` で生年月日と今日の差を出し、年齢に変換する部分で詰んだ。ミリ秒単位で返ってくるため、`1000 * 60 * 60 * 24 * 365.25` で割る必要があることを理解するのに時間がかかった。
- 一覧の中に作ったボタンへの対応：JavaScript で生成した「1回使った」ボタンは、最初から HTML にある要素と違い、生成した後でないとイベントを設定できない。`data-index` で何番目の項目かを持たせ、該当する項目だけを更新する仕組みを作った。
- 次回やりたいこと：項目を1件ずつ削除する機能、残り回数を点の数で可視化する機能、項目ごとに「相手の寿命」を基準にできる機能（祖父母との時間など）。また、今回は配列操作を `push` と `forEach` を用いたがAIをしようしたため完全に理解していないためにより理解を深めたい。

## ⑦フリー項目（感想、シェアしたいこと等なんでも）

  localStorage についてそもそもの理解を深めることに苦労しました。
